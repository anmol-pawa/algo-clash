# Algo Clash: Curriculum

What the game teaches, in what order, and to what depth. Language: **C++17/20** (libc++ in the browser, g++/clang natively for verification). Every lesson is original writing, built up from first principles. The problem "similar to" names point to well-known LeetCode problems for extra practice on the real site. Our statements, titles, examples and editorials are always our own.

---

## 1. Teaching method (applies everywhere)

1. **Worked example → faded example → independent problem.** Every region opens with a fully worked problem, then one with gaps (cloze or Parsons), then unaided problems.
2. **Blocked, then interleaved.** Inside a region, practice is blocked by pattern. The Daily Rift, gyms (phase 1), the Arena and the Tower are interleaved across regions.
3. **Retrieval over re-reading.** Lessons end with recall checks, never with a summary to re-read.
4. **Spaced repetition** of problems *and* templates (GAME_DESIGN §6.2).
5. **Elaboration.** Every editorial asks "why does this work?" and "when would it fail?".
6. **Calibration.** Confidence is collected before each submission and the gap is reported.
7. **Desirable difficulty.** Interview mode removes autocomplete, so the syntax lives in your hands, not in the IDE.

Each region's lesson is 5–12 short screens: motivation (a real interview-style scenario), concept, a picture (pixel diagram or a visualiser), a C++ idiom box, a worked example, pitfalls, and recall checks.

## 2. C++ for interviews: Syntax Shores and the "C++ Corner" in every region

The player starts with C++ from zero and ends writing idiomatic competitive and interview C++. Every item below gets a lesson screen, an idiom box, and wild-encounter cards: write-from-memory, predict-output, fix-the-compile-error (real clang messages, generated by compiling in tests) and spot-the-bug.

**S1 Program basics.** `main`, `#include`, `using namespace std` (and why it's acceptable in interviews but not in headers), `cin`/`cout`, `ios::sync_with_stdio(false)`, `'\n'` vs `endl`, fundamental types and their ranges, `int` vs `long long`, `size_t`, literals (`1LL`, `1e9`), integer division and modulo with negatives, implicit conversions and narrowing, `auto`.

**S2 Control flow and functions.** if/else, switch, loops, `break`/`continue`, functions, pass by value vs reference vs const reference (and why passing `vector<int>` by value causes TLE), return types, overloading, default arguments, recursion and the call stack (stack overflow in deep recursion), `static`.

**S3 Arrays, vectors and strings.**
- `std::array`; `vector` construction (`vector<int> v(n, 0)`, 2D `vector<vector<int>> g(n, vector<int>(m))`); `push_back` vs `emplace_back`; `reserve` vs `resize`; `back`, `pop_back`, `insert`, `erase` and their costs; range-for with `auto&` vs `const auto&`.
- `string`: indexing, `+=`, `substr(pos, len)` (cost!), `find`, `npos`, `to_string`, `stoi`/`stoll`, `char` arithmetic (`c - 'a'`), `isdigit`/`isalpha`/`tolower`, `stringstream` for splitting.

**S4 Structs and classes for LeetCode.** `struct` with constructors, member initialiser lists, `operator<` for sorting, `ListNode`/`TreeNode` as LeetCode defines them, `nullptr`, `new` (and the interview convention of not freeing), `class Solution { public: … };`, `this`.

**S5 STL containers.**
- `pair`/`tuple`, structured bindings `auto [a, b]`.
- `stack`, `queue`, `deque`.
- `priority_queue` (max by default; min via `greater<>`; custom comparator via a lambda + `decltype`, or a struct; the "comparator is reversed" gotcha).
- `set`/`multiset` (erasing one copy from a multiset!), `map`/`multimap`, `unordered_map`/`unordered_set` (average vs worst case, `reserve`, a custom hash for `pair`, anti-hash tests), `bitset`.
- The `map[key]` default-insert trap; `count` vs `find` vs `contains` (C++20).

**S6 Iterators and `<algorithm>`.**
- `sort` with comparators (strict weak ordering!), `stable_sort`.
- `lower_bound`/`upper_bound`/`equal_range` on sorted vectors **and** the member versions on `set`/`map` (`std::lower_bound` on a set is O(n), a classic pitfall).
- `binary_search`, `reverse`, `rotate`, `unique` + `erase`, `next_permutation`, `nth_element`, `partial_sort`, `min_element`/`max_element`, `accumulate` (the `0LL` pitfall), `iota`, `partial_sum`, `fill`, `count_if`, `find_if`, `all_of`/`any_of`, `transform`, `std::gcd`/`std::lcm`, `__builtin_popcount`/`clz`/`ctz` (and the `ll` variants), `numeric_limits`, `INT_MAX`/`LLONG_MAX`.

**S7 Lambdas and modern C++.** Lambdas and captures (`[&]` vs `[=]`), recursive lambdas (`function<int(int)>` vs `auto self` with a deducing parameter), `auto` return types, `const`, `constexpr`, `enum class`, `optional`, a light touch of `string_view`, ranges (C++20, read-only awareness).

**S8 Memory and safety.** Stack vs heap, `new`/`delete`, `unique_ptr`/`shared_ptr` (enough for interview conversation), dangling references, iterator invalidation (vector reallocation, erase-while-iterating), out-of-bounds UB, signed overflow UB, uninitialised variables.

**S9 The pitfall gallery** (Team Undefined's moves):
- `v.size() - 1` on an empty vector
- `int` overflow in `mid = (lo + hi) / 2` and in products
- comparing `int` with `size_t`
- `map[]` inserting
- modifying a container while iterating
- a non-strict comparator (`<=`) in `sort` causing crashes
- `abs` on `INT_MIN`
- floating-point equality
- a missing `return` in a non-void function
- reading uninitialised `dp` arrays
- `memset` with values other than 0/−1
- recursion depth on 10⁵-node linked structures.

**S10 Writing it fast by hand.** A personal snippet discipline (what to memorise, not paste), typing drills for idioms (e.g. the min-heap of pairs declaration, the 4-direction grid loop `int dr[]={-1,1,0,0}`), and reading clang errors quickly.

C++ Corner boxes in later regions introduce the idioms each pattern needs (e.g. Heap Highlands: comparator lambdas; Web Wilds: adjacency lists `vector<vector<int>>` vs `vector<vector<pair<int,int>>>`).

## 3. Regions, patterns and problem ladders

Ladder notation: **E** warm-up, **M** core, **H** boss tier. Counts are targets, and the routine may add more. Names in *italics* are the similar-to LeetCode problems used as pointers. Every pattern lists the **signals** players learn to spot.

### R0 Syntax Shores (C++ basics), §2 S1–S4
About 40 small "write this function" exercises (sum of digits, reverse a string, count vowels, FizzBuzz variants, matrix transpose, parse CSV line), each judged. Gym: *Mainville Gym*, a mixed 10-exercise gauntlet in Interview mode.

### R1 Scout School: complexity and constraints
Big-O/Θ/Ω, amortised analysis (vector doubling), reading loops and recursions, recurrence relations (Master theorem, recursion-tree method; solver-checked), space complexity, and the **constraint → complexity table** (n ≤ 10 → n!, ≤ 20 → 2ⁿ, ≤ 500 → n³, ≤ 5000 → n², ≤ 10⁶ → n log n, ≤ 10⁸ → n, larger → log n or O(1)). About 10⁸ simple ops per second native, and less in WASM (the judge calibrates). Card-only region plus the first **recognition blitz** format.

### R2 Array Atoll: arrays, hashing basics, two pointers, prefix sums
- **Hashing basics.** Signals: "seen before", "pair summing to", "group by", "count frequency". E: *Two Sum*, *Contains Duplicate*, *Valid Anagram*. M: *Group Anagrams*, *Top K Frequent Elements* (bucket sort), *Product of Array Except Self*, *Valid Sudoku*, *Longest Consecutive Sequence*, *Encode and Decode Strings*. H: *First Missing Positive* (index as hash).
- **Two pointers.** Signals: sorted input, pair/triple targets, palindromes, in-place partitioning. E: *Valid Palindrome*, *Move Zeroes*, *Remove Duplicates from Sorted Array*. M: *Two Sum II*, *3Sum*, *Container With Most Water*, *Sort Colors* (Dutch flag), *Boats to Save People*, *4Sum*. H: *Trapping Rain Water*.
- **Prefix sums and difference arrays.** Signals: many range-sum queries, subarray sum = k, range updates. E: *Range Sum Query – Immutable*. M: *Subarray Sum Equals K*, *Contiguous Array*, *Continuous Subarray Sum*, *Subarray Sums Divisible by K*, *Range Sum Query 2D*, *Car Pooling*, *Corporate Flight Bookings*. H: *Count of Range Sum* (revisited in the Citadel).
- **Kadane.** *Maximum Subarray*, *Maximum Sum Circular Subarray*, *Maximum Product Subarray*.
- Gym: **Tidecaller Mira** (two pointers and prefix sums).

### R3 Window Woods: sliding window and monotonic deque
Signals: contiguous subarray or substring, "longest/shortest with condition", a window constraint that is monotone. Covers fixed vs variable windows, the "at most K" → "exactly K" trick, and the monotonic deque window maximum.
- E: *Best Time to Buy and Sell Stock*, *Maximum Average Subarray I*.
- M: *Longest Substring Without Repeating Characters*, *Longest Repeating Character Replacement*, *Permutation in String*, *Minimum Size Subarray Sum*, *Fruit Into Baskets*, *Max Consecutive Ones III*, *Find All Anagrams in a String*.
- H: *Minimum Window Substring*, *Sliding Window Maximum*, *Subarrays with K Different Integers*, *Shortest Subarray with Sum at Least K* (prefix + deque; teaches why negatives break plain windows).
- Gym: **Pane Warden**.

### R4 Hashwood Harbor: hashing in depth
Hash table internals (chaining vs open addressing, load factor, rehash cost), designing keys (tuple or string encodings, sorted signatures), custom hash functions for `pair` and anti-hash defence, hash maps for state in other patterns, and rolling hash (Rabin–Karp).
- M: *Isomorphic Strings*, *Word Pattern*, *Insert Delete GetRandom O(1)*, *Brick Wall*, *Longest Substring with At Most K Distinct* (an original variant), *Repeated DNA Sequences* (rolling hash), *Design HashMap*.
- H: *Longest Duplicate Substring* (binary search + rolling hash), *Substring with Concatenation of All Words*.
- Gym: **Hydra of Hashwood**.

### R5 Chainlink Caves: linked lists
Pointers, the dummy node, fast/slow runners, in-place reversal, merging, cycle detection (Floyd, with a proof), and the pointer-diagram visualiser.
- E: *Reverse Linked List*, *Merge Two Sorted Lists*, *Linked List Cycle*, *Middle of the Linked List*.
- M: *Reorder List*, *Remove Nth Node From End*, *Add Two Numbers*, *Copy List with Random Pointer*, *Find the Duplicate Number*, *Palindrome Linked List*, *Intersection of Two Linked Lists*, *Sort List*, *Rotate List*, *Odd Even Linked List*.
- H: *Merge k Sorted Lists*, *Reverse Nodes in k-Group*.
- Design: *LRU Cache* (hash map + doubly linked list, written from scratch, and again with `std::list` + `splice`).
- Gym: **Chainwyrm Matriarch**.

### R6 Stackspire: stacks, queues and the monotonic stack
Signals: matching or nesting, "next greater/smaller", "previous", histogram areas, expression evaluation, undo.
- E: *Valid Parentheses*, *Min Stack*, *Implement Queue using Stacks*, *Baseball Game*.
- M: *Evaluate Reverse Polish Notation*, *Daily Temperatures*, *Car Fleet*, *Next Greater Element II*, *Asteroid Collision*, *Decode String*, *Online Stock Span*, *Sum of Subarray Minimums*, *Remove K Digits*, *Simplify Path*, *Design Circular Queue*.
- H: *Largest Rectangle in Histogram*, *Maximal Rectangle*, *Basic Calculator*, *Trapping Rain Water* (stack version).
- Gym: **Stackspire Sentinel**.

### R7 Recursion Ruins: recursion and divide & conquer
Recursion as induction, base cases, recursion trees, memoisation preview, merge sort (count inversions), quickselect, fast exponentiation, the Master theorem revisited, and tail calls.
- M: *Pow(x, n)*, *Kth Largest Element in an Array* (quickselect), *Sort an Array* (merge and quick), *Different Ways to Add Parentheses*, *Count Inversions* (original), *Merge Sort Linked List* (= *Sort List*).

### R8 Bisect Bay: binary search
Invariant-based binary search (`lo` is always bad, `hi` is always good; the half-open template), lower/upper bound, binary search on the answer (monotone predicate), rotated arrays, peaks, 2D matrices, real-valued search, and overflow-safe mid.

|---|---|

| "connected", "groups", dynamic merging | DSU |

## 7. Interview communication (coached throughout)

A five-step script, rehearsed in the Tower and shown in the Debrief:
1. Clarify inputs, outputs and edge cases.
2. Give the brute force and its complexity.
3. Find the bottleneck and optimise, naming the pattern.
4. Code cleanly with good names, talking through invariants.
